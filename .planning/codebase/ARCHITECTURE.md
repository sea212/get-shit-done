# Architecture

**Analysis Date:** 2025-02-27

## Pattern Overview

**Overall:** AI-Agent Orchestration Framework via CLI & Markdown

**Key Characteristics:**
- Prompt-driven orchestration (workflows defined as executable Markdown files)
- Stateless, file-based persistence (all state lives in `.planning/` directory)
- Specialized multi-agent system (sub-agents invoked for specific tasks)
- Node.js scripts providing deterministic tools for LLM

## Layers

**Input & Command Layer:**
- Purpose: Entry point for user interactions defining flags and core command goals.
- Location: `commands/gsd/*.md`
- Contains: Slash command definitions for Claude Code.
- Depends on: Workflows and templates.
- Used by: User via Claude Code interface.

**Workflow Orchestration Layer:**
- Purpose: Multi-step process definitions that guide the LLM through complex tasks. Handles branching, questioning, and AI agent spawning.
- Location: `get-shit-done/workflows/*.md`
- Contains: Executable step-by-step prompts.
- Depends on: CLI Tools (`gsd-tools.cjs`), AI Agent Definitions.
- Used by: Command Layer.

**Agent Layer:**
- Purpose: Provide specific personas, instructions, and guardrails for specialized AI tasks.
- Location: `agents/*.md`
- Contains: Prompts setting up role and context (e.g., `gsd-roadmapper`, `gsd-project-researcher`).
- Depends on: Shared project context.
- Used by: Workflow Orchestration Layer via `Task()` calls.

**CLI Utility / Service Layer:**
- Purpose: Provide deterministic file system, state, and Git operations to prevent bash-spaghetti.
- Location: `get-shit-done/bin/gsd-tools.cjs` and `get-shit-done/bin/lib/*.cjs`
- Contains: Core JavaScript functions handling state mutation, configuration parsing, frontmatter manipulation, and validation.
- Depends on: Node.js file system APIs, simple module dependencies.
- Used by: Workflow Orchestration Layer (`bash` command executions).

**Template Layer:**
- Purpose: Ensure uniformity of artifacts generated by the AI and user.
- Location: `get-shit-done/templates/`
- Contains: Markdown files with frontmatter definitions and structural skeletons.
- Depends on: None.
- Used by: CLI Utility Layer and AI Agents.

## Data Flow

**Command Execution Lifecycle:**

1. **Invocation:** User runs a slash command (e.g., `/gsd:new-project --auto`).
2. **Command Resolution:** Claude loads the definition from `commands/gsd/new-project.md`.
3. **Workflow Routing:** Command delegates execution to the relevant workflow (`get-shit-done/workflows/new-project.md`).
4. **Initialization:** Workflow calls `gsd-tools.cjs init <workflow>` to reliably load state and configuration from `.planning/`.
5. **Execution & Orchestration:**
   - Claude interprets steps sequentially.
   - For sub-tasks, Claude spawns specialized agents (e.g. `gsd-project-researcher`) using descriptions from `agents/`.
   - Claude interacts with the user via `AskUserQuestion`.
6. **Persistence:** Tool commands (`gsd-tools.cjs state update`, `commit`, etc.) strictly manage updates to `.planning/` files.

**State Management:**
- Stateless process model.
- Persistent state securely maintained in the `.planning/` directory (e.g., `STATE.md`, `ROADMAP.md`, `config.json`).
- Re-read at the start of every significant workflow via the Node CLI tools.

## Key Abstractions

**CLI Tool Hub (`gsd-tools.cjs`):**
- Purpose: Unify complex logic (frontmatter parsing, metric recording, validation) into a single, reliable point of contact for the LLM.
- Examples: `get-shit-done/bin/gsd-tools.cjs`, `get-shit-done/bin/lib/state.cjs`
- Pattern: CLI controller dispatching to domain-specific service files.

**Executable Workflow:**
- Purpose: Constrain LLM creativity into repeatable, highly-structured processes.
- Examples: `get-shit-done/workflows/plan-phase.md`, `get-shit-done/workflows/execute-phase.md`
- Pattern: Markdown document containing strict `<process>`, `<setup>`, and conditional blocks.

## Entry Points

**Claude Code CLI Commands:**
- Location: `commands/gsd/*.md`
- Triggers: User typing `/gsd:*` in Claude.
- Responsibilities: Set boundaries, argument limits, and inject contextual references for workflows.

**JavaScript Tooling CLI:**
- Location: `get-shit-done/bin/gsd-tools.cjs`
- Triggers: `bash` executions within workflows or hook scripts.
- Responsibilities: Expose deterministic functions (`state load`, `template fill`, `commit`) with robust file handling.

## Error Handling

**Strategy:** Fail fast in deterministic tools; recover gracefully in AI workflows.

**Patterns:**
- **JS Tools:** Throws descriptive errors (`process.exit(1)`) ensuring corrupt state is avoided (e.g., `error()` calls in `get-shit-done/bin/lib/core.cjs`).
- **Workflows:** Include specific instructions to handle tool failures (e.g. instructions handling "ROADMAP BLOCKED" in `workflows/new-project.md`). Prompt loops guide user intervention when blocking errors occur.

## Cross-Cutting Concerns

**Validation:**
- Frontmatter schemas and file completeness are centralized in `get-shit-done/bin/lib/verify.cjs` and `get-shit-done/bin/lib/frontmatter.cjs`.
- Ensures documents (like `PLAN.md` and `SUMMARY.md`) conform to rigid specs.

**Configuration & Customization:**
- Managed centrally via `get-shit-done/bin/lib/config.cjs` reading from `.planning/config.json` or fallback defaults.
- Dictates depth, verbosity, and model choices dynamically for agents.

**Extensibility:**
- Heavy reliance on prompt-as-code allows easy introduction of new slash commands, reference philosophies, or agents without heavy code refactoring.
