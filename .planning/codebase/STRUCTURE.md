# Codebase Structure

**Analysis Date:** 2025-03-04

## Directory Layout

```
get-shit-done/
├── agents/             # Agent role and prompt definitions
├── commands/           # GSD command documentation
│   └── gsd/            # Main command group
├── get-shit-done/      # Core assets and CLI implementation
│   ├── bin/            # CLI entry point and library
│   │   └── lib/        # Core domain modules
│   ├── templates/      # Markdown templates for .planning/
│   ├── workflows/      # Step-by-step procedure guides
│   └── references/     # Technical specs and design docs
├── hooks/              # Host AI environment hooks
├── scripts/            # Build and utility scripts
├── tests/              # Test suite
└── bin/                # NPM installer entry point
```

## Directory Purposes

**agents/:**
- Purpose: Defines the roles and instructions for various AI agents in the GSD system.
- Contains: Markdown files for `gsd-planner`, `gsd-executor`, `gsd-verifier`, etc.
- Key files: `gsd-planner.md`, `gsd-executor.md`.

**commands/gsd/:**
- Purpose: Documentation for all GSD commands, often used by the host AI to discover tool capabilities.
- Contains: Markdown files describing command usage, arguments, and examples.
- Key files: `plan-phase.md`, `execute-phase.md`, `verify-work.md`.

**get-shit-done/bin/:**
- Purpose: programmatic entry point for the GSD system.
- Contains: `gsd-tools.cjs` (CLI router) and `lib/` directory.

**get-shit-done/bin/lib/:**
- Purpose: Domain-specific logic modules.
- Contains: `.cjs` files for state management, phase operations, roadmap parsing, etc.
- Key files: `core.cjs`, `state.cjs`, `phase.cjs`.

**get-shit-done/templates/:**
- Purpose: Blueprints for generating project planning documents.
- Contains: Markdown templates for `PLAN.md`, `SUMMARY.md`, `STATE.md`, etc.

**get-shit-done/workflows/:**
- Purpose: Procedural instructions for complex multi-step operations.
- Contains: Markdown SOPs (Standard Operating Procedures).
- Key files: `plan-phase.md`, `execute-phase.md`.

**hooks/:**
- Purpose: Integration scripts for the host AI environment (Claude Code, Gemini, etc.).
- Contains: Scripts to automate updates, monitor context, and provide status lines.

## Key File Locations

**Entry Points:**
- `get-shit-done/bin/gsd-tools.cjs`: Primary CLI entry point.
- `bin/install.js`: NPM installation entry point.

**Configuration:**
- `get-shit-done/templates/config.json`: Blueprint for the project-level `.planning/config.json`.
- `package.json`: Project metadata and dependencies.

**Core Logic:**
- `get-shit-done/bin/lib/core.cjs`: Shared utilities and git integration.
- `get-shit-done/bin/lib/state.cjs`: STATE.md management engine.

**Testing:**
- `tests/`: Directory containing all test files.
- `scripts/run-tests.cjs`: Custom test runner.

## Naming Conventions

**Files:**
- JavaScript modules: lowercase hyphenated or camelCase (e.g., `gsd-tools.cjs`, `core.cjs`).
- Agent definitions: `gsd-<role>.md`.
- Command documentation: `<command-name>.md`.
- Workflow definitions: `<workflow-name>.md`.

**Directories:**
- Feature groups: lowercase hyphenated.

## Where to Add New Code

**New GSD Command:**
- Implementation: Add to `get-shit-done/bin/lib/commands.cjs` or a new module in `lib/`.
- Router: Add a case to `get-shit-done/bin/gsd-tools.cjs`.
- Documentation: Create a markdown file in `commands/gsd/`.

**New Planning Template:**
- Template: Add to `get-shit-done/templates/`.
- Logic: Add scaffolding logic to `get-shit-done/bin/lib/commands.cjs` (scaffold command).

**New Workflow:**
- Definition: Create a markdown file in `get-shit-done/workflows/`.
- Support: Ensure any required CLI commands are implemented in `lib/`.

**New Utility:**
- Shared helper: Add to `get-shit-done/bin/lib/core.cjs`.

## Special Directories

**.planning/:**
- Purpose: The database of the GSD system, stored within the user's project.
- Generated: No (but files inside are generated by GSD tools).
- Committed: Yes.
