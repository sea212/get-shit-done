<objective>
Implement `syncGeminiSettings` to automatically create and synchronize `.gemini/settings.json` with GSD agent model mappings.

Purpose: Automates model settings propagation so users do not manually configure `.gemini/settings.json`.
Output: Working, tested `syncGeminiSettings` function in `core.cjs`.
</objective>

<feature>
  <name>syncGeminiSettings logic</name>
  <files>get-shit-done/bin/lib/core.cjs, tests/core.test.cjs</files>
  <behavior>
    - If `process.env.GEMINI_CLI !== '1'`, does nothing and returns early.
    - Resolves `.gemini/settings.json` within the given `cwd`.
    - If it does not exist, prepares a clean config structure: `{ modelConfigs: { overrides: [] } }`.
    - If it exists, reads and parses it safely. Recreates the structure on JSON parse failure.
    - Generates overrides for all `Object.keys(MODEL_PROFILES)` via `resolveModelInternal(cwd, agent, { skipSync: true })`.
    - Assigns `modelConfig.safetySettings` as `BLOCK_NONE` for all categories (from `getGeminiSafetySettings()`).
    - Preserves existing user overrides where `match.overrideScope` does NOT start with `gsd-`.
    - Atomically writes the merged settings to a temp file and renames it to `.gemini/settings.json`, formatted with 2 spaces.
  </behavior>
  <implementation>
    Add `syncGeminiSettings(cwd)` to `core.cjs`. Export it for testing. Update `resolveModelInternal(cwd, agentType, options = {})` to accept options so we can pass `skipSync: true` inside the loop, preventing potential recursion. Do not wire the automatic sync trigger yet (that is next plan). Use a temp directory in `tests/core.test.cjs` to simulate `cwd` and verify the output structure.
  </implementation>
</feature>
